# ЗнанняПлюс — вебзастосунок освітнього центру

Лабораторна робота № 5 «Розроблення вебзастосунку з використанням технологій вайбкодингу».
Автор: Вискірко Олександр, група ФІТ 2-17.

Повноцінний вебзастосунок: клієнтська частина (HTML/CSS/JavaScript з ЛР № 3–4), сервер **Node.js + Express 5**,
база даних **SQLite** (вбудований модуль `node:sqlite`), **REST API** з автентифікацією та ролями.

## Можливості

| Роль | Що можна зробити |
|---|---|
| Гість | каталог курсів із фільтрами та сортуванням (запити до API), сторінка курсу з групами й вільними місцями, календар вільних слотів репетитора, заявка на консультацію, реєстрація |
| Учень | вхід / вихід, запис у групу або на індивідуальне заняття з оплатою й промокодом, особистий кабінет (розклад, скасування з правилом 12 годин, повернення коштів на баланс, видалення з історії), налаштування |
| Адміністратор | CRUD груп (створення з перевіркою перетину розкладу викладача, публікація/чернетка, видалення), CRUD курсів через API, опрацювання й видалення заявок на консультацію |

## Запуск локально

Потрібен **Node.js 22.13 або новіший** (https://nodejs.org).

```bash
npm install          # встановлює єдину залежність — express
cp .env.example .env # за бажанням: свої SESSION_SECRET і ADMIN_PASSWORD
npm start            # http://localhost:3000
npm test             # 24 інтеграційні тести API (node:test)
```

База даних `data/znannyaplus.db` створюється й заповнюється демонстраційними даними під час першого запуску.

Демо-облікові записи:

* учень — `ivan.petrenko@gmail.com` / `znannya2026` (кнопка «Увійти як демо-учень» на сторінці входу);
* адміністратор — `admin@znannyaplus.com.ua` / значення `ADMIN_PASSWORD` (у режимі розробки без `.env` — `Admin2026-dev`).

## Структура

```
server.js              точка входу (порт, БД, коректне завершення)
src/config.js          конфігурація зі змінних середовища
src/db.js              схема БД (6 таблиць), відкриття, транзакції
src/seed.js            демонстраційні дані
src/security.js        хешування паролів (scrypt), підписані cookie, CSRF, rate limit, заголовки безпеки, ролі
src/validate.js        серверна валідація (422 з помилками полів)
src/schedule.js        розклад груп, перетин занять
src/routes/*.js        маршрути REST API
public/                клієнт: 14 HTML-сторінок, css/, js/ (api.js — клієнт REST API)
test/api.test.js       інтеграційні тести
docs/AI-LOG.md         журнал взаємодії з ШІ (промпти, відповіді, зміни)
render.yaml            опис розгортання на Render
```

## REST API

Усі відповіді — JSON. Помилки: `{ "error": "текст", "fields": { "поле": "текст" } }` зі статусами
400, 401, 403, 404, 409, 413, 422, 429. Запити, що змінюють дані, мають містити заголовок `X-Requested-With: ZP` (захист від CSRF).

| Метод | Шлях | Доступ | Опис |
|---|---|---|---|
| GET | `/api/health` | усі | стан сервера |
| POST | `/api/auth/register` | усі | реєстрація `{name, email, password}` |
| POST | `/api/auth/login` | усі | вхід, встановлює HttpOnly-cookie сесії |
| POST | `/api/auth/logout` | усі | вихід |
| GET | `/api/auth/me` | учень, адмін | поточний користувач (401 для гостя) |
| GET | `/api/auth/session` | усі | `{user}` або `{user: null}` |
| GET | `/api/courses` | усі | список: `subject, level, format, age, q, min, max, sort, limit` |
| GET | `/api/courses/:id` | усі | курс з програмою й опублікованими групами |
| POST / PUT / DELETE | `/api/courses[/:id]` | адмін | створення, зміна, видалення курсу |
| GET | `/api/groups` | усі (`?all=1` — з чернетками для адміна) | групи, фільтр `course` |
| GET | `/api/groups/:id` | усі | група |
| POST | `/api/groups` | адмін | створення (перевірка перетину розкладу → 409) |
| PATCH | `/api/groups/:id` | адмін | статус, кількість місць, розклад |
| DELETE | `/api/groups/:id` | адмін | видалення (409, якщо є записані учні) |
| GET | `/api/promo/:code` | усі | перевірка промокоду |
| GET | `/api/slots?tutor=` | усі | зайняті індивідуальні слоти |
| GET | `/api/bookings` | учень | власні записи |
| GET | `/api/bookings/:id` | учень | запис |
| POST | `/api/bookings` | учень | оплата й запис `{kind, groupId \| slotAt, promo, method}` — ціну рахує сервер |
| PATCH | `/api/bookings/:id` | учень | скасування `{status:'cancelled', refund}` (не пізніше ніж за 12 год) |
| DELETE | `/api/bookings/:id` | учень | видалення скасованого або минулого запису з історії |
| POST | `/api/consultations` | усі | заявка на консультацію |
| GET / PATCH / DELETE | `/api/consultations[/:id]` | адмін | перегляд, зміна статусу, видалення |

## Розгортання (Render)

1. Завантажте репозиторій на GitHub.
2. На https://render.com → **New → Blueprint** → оберіть репозиторій (файл `render.yaml` уже налаштований).
3. Задайте `ADMIN_PASSWORD`; `SESSION_SECRET` згенерується автоматично.

На безкоштовному тарифі файлова система тимчасова: після перезапуску база даних створюється заново з демонстраційними даними.
